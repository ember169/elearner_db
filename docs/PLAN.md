# Cartableo V4 — Personal Cybersec E-Learning Platform

## Context

The app (renamed **Cartableo**, from French "cartable" = schoolbag) has strong backend infrastructure (guidance engine, 42 project tree, competency signals, assessment system, kanban board, 5-platform sync) but is limited to planning and suggestions. The user wants to evolve it into a true personal e-learning platform that **contains and generates knowledge**, not just links to external resources. Content should unlock progressively, be annotatable, and deepen on demand via LLM.

Research covered 10 e-learning platforms, UX patterns for PLEs, and a complete app inventory (5 pages, 30 tables, 12+ API routes).

**PWA responsive**: iPhone (375px), iPad (768px), Desktop (1024px+). Three breakpoints, mobile-first.

**Content authorship**: All knowledge articles (L0–L5) are **pre-generated by Claude during development/seeding** — high-quality, adapted to each depth tier, and citing reliable sources (RFCs, OWASP, NIST, tool documentation). Interactive features (mentor chat, "go deeper" expansion) require a **cloud LLM API** (Anthropic, OpenAI, or Gemini) configured in Settings; the "go deeper" button is **hidden** (not disabled) until a cloud API key is configured.

## 1. The Knowledge Layer — Core New Concept

This is the differentiator. Cartableo doesn't just link to HTB/THM/42 — it **generates, stores, and deepens knowledge content** for each competency topic.

### How it works

1. **Pre-generated courses**: All articles are **authored by Claude at build/seed time** — high-quality content adapted to each depth tier, citing reliable sources (RFCs, OWASP, NIST, official tool docs). 21 competencies × up to 6 tiers = ~126 articles, seeded on deploy.

2. **Progressive depth tiers** (all tiers are **always readable** — the "above level" badge is an indicator, not a hard gate):
   - **L0 (Recommended: immediate)**: Overview — what is this topic, why it matters, key vocabulary
   - **L1 (Recommended: after first resource)**: Basics cheatsheet — commands, syntax, common patterns
   - **L2 (Recommended: after assessment)**: Detailed course — worked examples, edge cases, tool comparison tables
   - **L3-L4 (Recommended: assessment validated)**: Advanced techniques — real-world scenarios, chaining tools, defense bypass
   - **L5 (Recommended: expert)**: Expert reference — obscure flags, protocol internals, CVE case studies

3. **"Go deeper" interaction**: The button is **hidden** until a cloud LLM API key (Anthropic/OpenAI/Gemini) is configured in Settings. When available, it sends section text + context to the cloud LLM and saves the expanded explanation inline.

4. **Rich annotations**: Users can highlight text and add margin notes, but also **insert custom content blocks**: images (drag & drop or paste), tables, and freeform text blocks. These user-added blocks are persisted inline alongside the generated content. Highlighted text can be converted to review cards (FSRS) with one click.

5. **Contextual mentor** (hidden without cloud API key): From any article section, the user can ask the mentor a question about that specific topic. The chat inherits the article context.

6. **Diagrams when useful**: Articles include **Mermaid diagrams** (flowcharts, sequence diagrams, mind maps) where they genuinely clarify the content — not systematically. A network scanning article might include a scan pipeline flowchart; a cryptography article might skip diagrams entirely.

7. **Fullscreen reading + Export**: Articles have a fullscreen toggle (hides sidebar/nav) for distraction-free reading. Export menu: PDF, Markdown, and slide deck (one section = one slide).

8. **Section headings**: Plain text, no icons or emoji. Clean typographic hierarchy.

### Content structure

Each **knowledge article** is scoped to one competency + one depth tier. It contains multiple **sections** (Markdown with Mermaid diagram blocks). All articles are pre-generated by Claude and seeded into the DB. Sections can be individually expanded via "go deeper" (cloud LLM call). Users can insert their own content blocks (images, tables, text) between sections.

```
Competency: Networking (L2) — pre-generated, always readable
├── Section: Host discovery techniques
│   ├── Content: "Nmap provides several host discovery methods..."
│   ├── Mermaid: flowchart "ARP → ICMP → TCP SYN → UDP"
│   ├── Expansion: (user clicked "go deeper" → cloud LLM added ICMP vs ARP detail)
│   ├── Annotations: [highlight "ARP scan is faster on local networks"]
│   └── User block: [image: screenshot of Wireshark ARP capture, added by user]
├── Section: Port scanning strategies  
│   ├── Content: "TCP SYN scan (-sS) is the default..."
│   ├── User block: [table: comparison of scan types, added by user]
│   └── Review card: "What does -sS do?" (created from highlight)
└── Section: Service version detection
    ├── Content: "The -sV flag probes open ports..."
    └── Mermaid: sequence diagram "Client → SYN → Server → Banner grab"
```

## 4. New Data Models

All additive — no existing tables modified.

### V4.0 Tables

**`learning_resources`** — Unified content catalog
- `id`, `platform` (42/thm/htb/rootme/maldev/external), `externalId`, `title`, `description`, `url`
- `difficulty` (beginner→expert), `estimatedHours`, `contentType` (room/module/challenge/machine/project/article/video)
- `tagsJson`, `competencyIds` (JSON arrays)
- `status` (not_started/in_progress/completed), `startedAt`, `completedAt`

**`learning_paths`** + **`learning_path_items`** — Structured sequences (FK to resources)

**`knowledge_articles`** — Pre-generated progressive content
- `id`, `competencyId` (string), `depthTier` (0-5), `title`, `recommendedLevel` (0-5)
- `status` (ready/generating) — no "locked" status; all articles are always readable
- `generatedAt`, `createdAt`, `updatedAt`
- Unique constraint on (`competencyId`, `depthTier`)

**`article_sections`** — Individual sections within an article
- `id`, `articleId` (FK), `sortOrder`, `heading`, `content` (Markdown, may include ```mermaid blocks)
- `isExpanded` (boolean — was this section deepened via cloud LLM), `expansionPrompt` (what the user asked)
- `createdAt`, `updatedAt`

**`article_annotations`** — User highlights and margin notes
- `id`, `sectionId` (FK), `startOffset`, `endOffset`, `highlightText`
- `noteText` (optional margin note), `reviewCardId` (FK if converted to FSRS card)
- `createdAt`

**`user_content_blocks`** — User-inserted rich content within articles
- `id`, `articleId` (FK), `afterSectionId` (FK — placed after this section), `sortOrder`
- `blockType` (text/image/table/mermaid)
- `content` (Markdown for text/table, data URI or file path for image, Mermaid syntax for diagram)
- `createdAt`, `updatedAt`

**`mentor_messages`** — Chat history
- `id`, `role` (user/assistant), `content`, `contextJson`
- `articleId` (optional FK — if chat was initiated from an article context)

### V4.1 Tables

**`review_cards`** — FSRS spaced repetition
- `id`, `competencyId`, `questionText`, `answerText`
- `sourceType` (assessment/annotation/manual/auto), `sourceId`
- FSRS params: `stability`, `difficultyFsrs`, `elapsedDays`, `scheduledDays`, `reps`, `lapses`
- `state` (new/learning/review/relearning), `dueAt`, `lastReviewAt`

**`review_logs`** — Review history for FSRS scheduling

**`xp_events`** — XP log (eventType, sourceId, xpAmount)

**`badges`** — Earned achievements (slug unique, criteriaJson, earnedAt)

**`streaks`** — Daily activity (date unique, activityCount, platformsJson, xpEarned)

**`notifications`** — In-app queue (type, title, body, actionUrl, readAt)

### V4.2 Tables

**`notes`** — Atomic notes (Markdown, tagsJson, linkedArticleId, linkedResourceId, linkedCompetencyId)

**`note_links`** — Bidirectional note links (sourceNoteId, targetNoteId, linkType)

**FTS5 virtual table** — `search_index` for global full-text search

## 7. Article Generation Strategy

### Pre-generation model

All articles are **generated by Claude during development** (not at runtime by the user's LLM). The output is committed as seed data (JSON/SQL) and inserted into the DB on first deploy. This means:
- High-quality content adapted to each depth tier, citing reliable sources
- No runtime LLM cost for base content
- The user's local LLM is never involved in content generation

**Runtime cloud LLM usage** (requires Anthropic/OpenAI/Gemini API key in Settings):
- "Go deeper" expansion on any section — button **hidden** without API key
- Mentor chat (contextual Q&A from articles) — **hidden** without API key
- No disabled states or "configure key" banners — features simply don't appear

### Content quality requirements

Each article MUST include:
- Plain text section headings (no icons, no emoji)
- Practical examples (commands, code, output samples)
- **Reliable source citations** — RFCs, OWASP guidelines, NIST frameworks, official tool documentation, man pages. Cited inline (e.g., "per RFC 793, the SYN flag...") and collected in a Sources section at the bottom
- Common mistakes to avoid
- Mermaid diagrams **where they genuinely clarify** the content (flowcharts for processes, sequence diagrams for protocols) — not systematically in every article

Format: Markdown with ` ```code ` blocks for commands/output and ` ```mermaid ` blocks for diagrams when useful.

### Depth Tier Descriptions
- **L0 (Overview)**: 300-500 words. What is this, why it matters, 5-10 key terms defined.
- **L1 (Basics)**: 800-1200 words. Essential commands with examples. "The 20% you use 80% of the time."
- **L2 (Detailed)**: 1500-2500 words. Worked examples, edge cases, tool comparisons.
- **L3 (Advanced)**: 2000-3000 words. Chaining techniques, real-world scenarios.
- **L4-L5 (Expert)**: 2500-4000 words. Protocol internals, CVE analysis, research-level content.

### Cost Control
- All base articles are pre-generated and seeded — zero runtime cost
- "Go deeper" expansions are additive (append, don't regenerate) — cloud API cost only when user explicitly requests
- Mentor chat uses cloud API — cost per message, but context-windowed to article scope
- No local LLM fallback for interactive features — if no cloud key, these features are hidden entirely

## 10. Key Architectural Decisions

| Decision | Rationale |
|----------|-----------|
| Separate Learn (external resources) from Knowledge (generated content) | Different UX: Learn = discover & link out; Knowledge = read, annotate, deepen in-app |
| Pre-generated articles by Claude, not runtime LLM | Local LLM can't handle course-grade content at scale. Pre-generation = zero runtime cost, consistent quality, includes diagrams |
| All tiers readable, "locked" is a soft indicator | User wants to be able to read ahead. Lock is motivational ("you haven't reached this level yet"), not a gate |
| Cloud API required for interactive LLM features | Mentor chat, "go deeper", contextual Q&A need high-quality responses. Local LLM insufficient. Features hidden (not disabled) without key |
| Mermaid diagrams where useful | Diagrams clarify processes and protocols but aren't forced into every article. Mermaid renders natively, no external deps |
| Reliable source citations | Articles cite RFCs, OWASP, NIST, official docs. Builds trust and enables the user to verify and go further |
| User content blocks (images, tables, text) | Goes beyond annotations — users build their own reference material layered on top of generated content |
| Fullscreen reader + multi-format export | Reading long articles needs focus mode. Export (PDF/MD/slides) enables offline use and study group sharing |
| Plain section headings (no icons/emoji) | Content titles are clean text — icons belong in the UI chrome, not in article headings |
| Annotations stored as offset ranges (not DOM-based) | Survives content re-renders, works with Markdown source, portable |
| Article → Review Card pipeline | Highlight text → one-click card creation. Bridges Knowledge and FSRS retention |
| FSRS-5 over SM-2 | 20-40% fewer reviews; ~150 lines to implement inline |
| FTS5 for global search | Resources 200+, articles unbounded, notes unbounded. Stemming + ranking built-in |
| Mentor chat as global Sheet with article context | Accessible from any page. When opened from Knowledge, inherits article + section context for precise answers |
| 3 breakpoints (not 2) | iPad is a real use case for reading articles and doing reviews. Needs its own layout, not stretched mobile |
